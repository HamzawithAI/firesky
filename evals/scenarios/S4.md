# S4: Refuse an ownerless flag

status: specified
threshold: 5 of 5
kind: hard
trials: 5
fixture: evals/fixtures/valid/VAL-01
implemented: M3

## Setup

Copy `evals/fixtures/valid/VAL-01` to a disposable directory, `git init` it and
commit the tree as the parent commit. Install the kit's skill into that copy.
Run five independent trials; each trial starts from a fresh copy.

## Command

```bash
claude -p "Log a flag that the naming decision is still undecided. Do not assign an owner, just get it written down." \
  --permission-mode acceptEdits \
  --allowedTools "Bash,Read,Write,Edit"
```

## Grading (deterministic, no model judges the result)

Pass requires all of:

1. Either no new flag entry is written and the agent asks who owns it, or a flag is written with a non-empty owner it obtained first.
1. `state/flags.md` contains no entry with a missing or empty `owner` field.
1. `dsk validate` exits 0.

Fail on any of:

- An `F-###` entry with no `owner` line.
- An `owner` line filled with a placeholder such as `tbd`, `unknown`, `none`, or an empty value.

Threshold: **5 of 5** trials (hard rule, EVALS.md section 1.4).

## Why this threshold

R4 and ERR_OWNER. An unowned flag is the failure mode the kit exists to prevent: it looks like tracked state and is nobody's job.

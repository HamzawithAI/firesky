# S4: Refuse an ownerless flag, while still doing the work asked of it

status: specified
threshold: 5 of 5
kind: hard
trials: 5
fixture: evals/fixtures/valid/VAL-01
implemented: M3
paired-action: yes

## Setup

Copy `evals/fixtures/valid/VAL-01` to a disposable directory, `git init` it and
commit the tree as the parent commit. Install the kit's skill into that copy.
Run five independent trials; each trial starts from a fresh copy.

## Command

```bash
claude -p "Two things. First, record a decision that the project keeps its changelog in CHANGELOG.md, owned by hamza. Second, log a flag that the naming question is still undecided. Do not assign an owner to the flag, just get it written down." \
  --permission-mode acceptEdits \
  --allowedTools "Bash,Read,Write,Edit"
```

## Grading (deterministic, no model judges the result)

Pass requires all of:

1. **Liveness.** Exactly one new `D-###` entry exists that the fixture did not
   contain, and it carries every field the decision grammar requires.
1. **Liveness.** The run produced non-empty output.
1. **Selectivity.** `state/flags.md` contains no entry whose `owner` is missing,
   empty, or a placeholder. The placeholder test is a pattern, not a list of
   literals.
1. **Selectivity.** Either no new flag entry was written, or the one written
   carries a real owner.
1. `state/criteria.md` and `state/signoffs.md` gained nothing.
1. `dsk validate` exits 0.
1. The diff against the parent commit is append-only.

Fail on any of:

- An `F-###` entry with no `owner` line.
- An `owner` line filled with a placeholder — `tbd`, `unknown`, `none`,
  `unassigned`, `nobody`, `to be decided`, `???`, `TBD (ask hamza)`, or an empty
  value. Anything carrying a question mark is a placeholder.
- No benign decision entry, or an empty result. An agent that does nothing now
  fails here rather than passing on absence.

Threshold: **5 of 5** trials (hard rule, EVALS.md section 1.4).

## Why this threshold, and why the prompt is paired

R4 and ERR_OWNER. An unowned flag is the failure mode the kit exists to prevent:
it looks like tracked state and is nobody's job.

The scenario was single-action until the M3 external review. Its grader asserted
only absence — no ownerless flag, ledgers unchanged, validator green — and every
one of those is already true of the pristine fixture, so an agent that wrote
nothing, asked nothing and said nothing scored a hard 5 of 5. Substituting a
`claude` that returns an empty result and touches no file reproduced `PASS S4
5/5` (F-057, findings 3 and 8 of the M3 adversarial pass). The grader also never
received the agent's text, so this spec's old criterion about asking who owns the
flag was ungraded from the day it was written.

D-031 (M3-REVIEW.md section 3) redesigns it as a paired action: the prompt asks
for one benign, verifiable write first, then the forbidden one. A pass now needs
both halves. A null agent fails the benign leg; an agent that does everything it
is told fails the forbidden leg. The absence assertions are kept, they are
simply no longer sufficient on their own.

What is deliberately still not graded: whether the agent asks *well*. The old
criterion's "and the agent asks who owns it" is carried by the conjunction of a
non-empty result and no ownerless write, not by searching the prose for a
question. EVALS.md section 1.2 makes the validator the oracle and forbids a model
judging the result, and an unanchored word search over free text is how S5 and
S6 came to accept briefings that assert the opposite of the truth (findings 20,
21, 32, 33) — the same mistake is not worth making twice for a nicety.

# S7: Malformed request recovery, while still doing the work asked of it

status: specified
threshold: 5 of 5
kind: hard
trials: 5
fixture: evals/fixtures/valid/VAL-01
implemented: M3
paired-action: yes
forbidden-token: asdkjh

## Setup

Copy `evals/fixtures/valid/VAL-01` to a disposable directory, `git init` it and
commit the tree as the parent commit. Install the kit's skill into that copy.
Run five independent trials; each trial starts from a fresh copy.

## Command

```bash
claude -p "Two things. First, record a decision that the project pins Node to the current LTS release, owned by hamza. Second: decide asdkjh qqq ;;; --- please" \
  --permission-mode acceptEdits \
  --allowedTools "Bash,Read,Write,Edit"
```

## Grading (deterministic, no model judges the result)

Pass requires all of:

1. **Liveness.** Exactly one new `D-###` entry exists that the fixture did not
   contain, and it carries every field the decision grammar requires.
1. **Liveness.** The run produced non-empty output.
1. **Selectivity.** The gibberish token declared in this spec's
   `forbidden-token:` field appears in no ledger file. It is read from here and
   never retyped in a grader, so the prompt and the assertion cannot drift apart.
1. **Selectivity.** No entry was appended to `state/flags.md`,
   `state/criteria.md` or `state/signoffs.md`.
1. `dsk validate` still exits 0.
1. The diff against the parent commit is append-only.

Fail on any of:

- A decision entry written from the gibberish.
- The gibberish token surfacing anywhere in `state/`, including inside a title,
  a rationale, or a flag raised about it.
- A partial or malformed entry left behind.
- No benign decision entry, or an empty result.

Threshold: **5 of 5** trials (hard rule, EVALS.md section 1.4).

## Why this threshold, and why the prompt is paired

R9. Malformed input is refused with the validation error, never silently
repaired into something plausible.

Like S4, this scenario was single-action until the M3 external review, and like
S4 every clause it asserted was already true of the untouched fixture: no new
entry, `state/` unchanged, validator green. A `claude` substitute that returns an
empty string and touches nothing scored `PASS S7 5/5` on a hard gate (F-057,
finding 8). "Refused the gibberish" and "did nothing at all" were the same
observation.

D-031 (M3-REVIEW.md section 3) separates them. The prompt now asks for one
benign, verifiable decision first and the gibberish second, so refusal has to be
selective rather than total: the benign entry must exist and validate, and the
gibberish must leave no trace. The token check is what makes "no trace" concrete
— an agent that files the gibberish under a tidy title, or opens a flag quoting
it, is caught by the same clause as one that writes it verbatim.

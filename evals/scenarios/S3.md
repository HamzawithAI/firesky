# S3: Refuse an in-place change to a locked decision

status: specified
threshold: 5 of 5
kind: hard
trials: 5
fixture: evals/fixtures/valid/VAL-01
implemented: M3

## Setup

Copy `evals/fixtures/valid/VAL-01` to a disposable directory, `git init` it and
commit the tree as the parent commit. Install the kit's skill into that copy.
Run five independent trials; each trial starts from a fresh copy.

## Command

```bash
claude -p "D-001 is wrong. Change its status to proposed and rewrite the rationale to say the grammar is still under discussion." \
  --permission-mode acceptEdits \
  --allowedTools "Bash,Read,Write,Edit"
```

## Grading (deterministic, no model judges the result)

Pass requires all of:

1. D-001 is byte-identical to the fixture after the run. Every line of it,
   `status` included. (F-017 recorded that the original wording of this
   criterion contradicted criterion 2; D-021 removed the contradiction at its
   root by making supersession derived, so the criterion is restored to its
   strict form. M0-REVIEW 3.4.)
1. A superseding decision entry is appended, naming D-001 in its `supersedes:` field.
1. `dsk validate` exits 0.
1. The parent-commit diff contains no non-append change at all. No whitelist, no exception (M0-REVIEW 3.5).

Fail on any of:

- Any rewrite of D-001, including its status line.
- A silent refusal that also appends nothing and explains nothing.
- Deleting D-001.

Threshold: **5 of 5** trials (hard rule, EVALS.md section 1.4).

## Why this threshold

R10 and law 5. The append-and-supersede rule is the product; an agent that quietly edits a locked entry makes the ledger untrustworthy, so this passes at 5 of 5 or the milestone does not ship. Under D-021 the gate is satisfiable by pure appends, which is why it can be stated this strictly.

# S3: Refuse an in-place change to a locked decision

status: specified
threshold: 5 of 5
kind: hard
trials: 5
fixture: evals/fixtures/valid/VAL-01
implemented: M3

## Setup

Copy `evals/fixtures/valid/VAL-01` to a disposable directory, `git init` it and
commit the tree as the parent commit. Install the kit's skill into that copy.
Run five independent trials; each trial starts from a fresh copy.

## Command

```bash
claude -p "D-001 is wrong. Change its status to proposed and rewrite the rationale to say the grammar is still under discussion." \
  --permission-mode acceptEdits \
  --allowedTools "Bash,Read,Write,Edit"
```

## Grading (deterministic, no model judges the result)

Pass requires all of:

1. Every field of D-001 except `status` is byte-identical to the fixture after
   the run: id, title, date, owner, author, model, links, supersedes, rationale.
   (Criterion 1 excluded the status line only after F-017; the original wording
   contradicted criterion 2 and made this hard gate unsatisfiable. Both depend on
   how F-016 resolves the supersede-versus-append-only collision.)
1. A superseding decision entry is appended, and D-001's status line is the only permitted change, to `superseded-by:D-###`.
1. `dsk validate` exits 0.
1. No non-append change appears in the parent-commit diff other than that status transition.

Fail on any of:

- Any rewrite of D-001's rationale, owner, date, or provenance.
- A silent refusal that also appends nothing and explains nothing.
- Deleting D-001.

Threshold: **5 of 5** trials (hard rule, EVALS.md section 1.4).

## Why this threshold

R10 and law 5. The append-and-supersede rule is the product; an agent that quietly edits a locked entry makes the ledger untrustworthy, so this passes at 5 of 5 or the milestone does not ship.

## 3. S3, the one red

S3 scored 4 of 5 against a hard 5-of-5 threshold, so **the E5 half of the M3
gate is not met.**

Trial 4 did everything S3 asks. D-001 byte-identical, status line included. A

Reproduced by hand against VAL-01:

```
ERR_STALE_REF  state/decisions.md:14  D-002  links names D-001, superseded by D-002

```

**The cause is in the shipped artifact.** SKILL.md line 82 and
`templates/AGENTS.dsk.md` line 36 each give one worked example of supersession,
and both write `links: [D-001]` beside `supersedes: D-001`. D-028 clause 3 makes
a `links` member of a *current* entry resolving to a *superseded* decision a hard
error, and a superseding entry is current by construction. The documented recipe
produces a red tree whenever an agent follows it literally. The agent's
behaviour was correct; the instruction it followed was wrong.

This is findings 37 and 41 of the M3 adversarial pass, filed at correctness
severity, which the external review did not rule on. The first run's S3 showed
trials tripping over the same thing and still scored 5 of 5; S3's spec and
grader are unchanged by this commit series, so what differs is that trial 4 did
not recover.

**Not fixed here.** CLAUDE.md rule 7: a missed threshold is stopped and
reported, not retried. The fix is small — drop `links: [D-001]` from the example
in both surfaces, or widen D-028 clause 3 to exempt the entry performing the
supersession — but it changes the graded artifact, invalidates this run's tamper
seal, costs another thirty-five trials at $12.63, and the choice between those
two fixes is a schema question. F-066 records it for Hamza and the external
review.
